**This case study is about this website, not a client engagement.** It is small,
and it does not show how we operate infrastructure at client scale. What it does
show is how we make and document engineering decisions, and you can check the
security details below yourself by reading this site's response headers.

## Security posture

- **A Content Security Policy with one deliberate trade-off.** `script-src`
  allows `'unsafe-inline'`. We first shipped per-request nonces, then found they
  forced every page to render dynamically, because Next.js streams its own inline
  scripts into each document. We chose static rendering and
  [wrote up the reasoning and the cost](/insights/csp-nonce-killed-static-rendering).
  `unsafe-eval` is excluded in production. The other directives stay strict:
  `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`,
  `frame-ancestors 'none'`, and a closed `connect-src` allowlist.
- **Security headers on every route** - HSTS, frame denial, `nosniff`, a referrer
  policy, and a locked-down permissions policy.
- **Analytics storage is off until you choose.** Google Analytics runs in Consent
  Mode with storage denied by default. Google's tag still loads and sends a
  cookieless request before a choice is made, but no analytics cookies are set
  unless the visitor accepts.

## Quality checks

We run these before release:

- **TypeScript in strict mode** - the whole codebase, no `any` escape hatches in
  the app surface.
- **Playwright end-to-end tests** covering route status codes, navigation, form
  behavior, and layout overflow at mobile, tablet, and desktop viewports.
- **Automated accessibility checks** - axe-core runs against real rendered pages
  in the Playwright suite. Automated checks catch only part of what a manual
  accessibility review would.
- **A copy linter** - a small custom script, run with lint, that fails on
  typographic violations, because consistency is a delivery concern too.

## Integrations that fail loudly, not silently

The forms depend on external email delivery and spam protection. When a credential
is missing or a provider fails, the visitor is told plainly and given a direct way
to reach us. A genuine submission is never reported as sent when it was not.

## The stack

Next.js (App Router), React and TypeScript in strict mode, Tailwind CSS, Playwright
and axe-core for testing, deployed on Vercel.

## The honest caveat
